# Write issue

Create a new issue/ticket for this repository, matching my speech patterns and the project's existing templates/conventions.

For this you should:

1. Inspect the remotes with `git remote -v`. Decide from this if the remote is GitHub, GitLab, or something else.
2. Look up if there are issue templates in this repository (e.g. `.github/ISSUE_TEMPLATE/` for GitHub, `.gitlab/issue_templates/` for GitLab). Note the available types (bug, user story, technical story, ...) and their structure.
3. Check out the examples in `./references` to learn my personal writing style.
4. Look at the last couple of issues I wrote in this repository using `gh issue list --author <me>` or `glab issue list --author <me>`, so the new issue is consistent with recent ones.
5. Check what information I've already supplied about the issue. If anything required by the matching template is missing or ambiguous, ask me — but only ask what you genuinely need; don't make me repeat things you can infer from the repo or templates.
6. Pick the template that best fits the issue type and draft the issue, following the project's template structure and my style from step 3.
7. Show me the drafted issue and ask for confirmation before creating it. Only run `gh issue create` / `glab issue create` (or equivalent) once I've approved.

## Examples

Examples of issues I've written, pulled from past GitHub issues, can be found at `./references`. Take a look at them and copy the style like tone, structure, and how much detail to include. Note that the templates from the project should be used if there are any.
